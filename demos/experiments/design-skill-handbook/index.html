03 · 推荐的工作顺序

  1. 确定方向：先描述产品用户、核心任务、视觉参考和不希望出现的设计套路。
  2. 完成结构：用现有 Design Tokens、组件和真实数据实现页面，优先建立可访问的结构。
  3. 分项精调：只挑最突出的 1–2 个问题使用对应 Skills（文字、配色、布局或交互）。
  4. 审查动效：判断哪些过渡真正帮助理解状态，减少不必要的动画。
  5. 验收边界：测试 390/768/1280 px、长文本、空列表、键盘焦点、减少动画、低性能模式。
  6. 固化经验：将确认有效的设计约束写入项目 DESIGN.md，避免下次回归。

04 · 可直接交给 Agent 的任务示例

审核并改进项目 UI

审查当前页面的信息层级、字体、间距、配色和响应式。先列出最影响使用体验的 5 个问题及证据，只修复这些问题。沿用现有 Design Tokens 和组件，不添加无意义的装饰、渐变与动画。实现后用长文本、空态、键盘及 390/768/1280px 进行验收。

改善动画，而不是增加动画

检查当前项目所有过渡。区分“帮助用户理解状态”的动画和“纯装饰”动画；为必要过渡定义 duration、easing、transform/opacity 属性和中断机制，并提供 prefers-reduced-motion 降级。不要仅凭 CSS 检查声称视觉验收完成。
维护原则：记录来源、问题场景与验证日期；Skill 不是设计标准本身，不应替代浏览器实测。查看可编辑 Markdown 文档。
