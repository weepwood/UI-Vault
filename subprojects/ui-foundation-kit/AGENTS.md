# UI Foundation · Agent Design Rules

当 AI Agent 在本仓库或接入本基础包的项目中开发 UI 时，执行以下规则：

## 目标

交付简洁、现代、可读、可用的界面。以真实使用场景优先，不追求模板式「科技感」。

## 必须遵守

1. **内容优先**：每个标题、说明、标签必须服务于操作决策；删除重复介绍、无效英文、无意义数字。
2. **设计 Token**：优先使用 `--ui-*` 语义 Token；不在组件里大量硬编码色值、阴影、圆角、动效时间。
3. **图标唯一来源**：使用 Lucide 对应框架包；图标尺寸默认 16/18px、stroke-width 约 1.8–2，图标按钮标注 `aria-label`。
4. **状态完整**：至少覆盖 default/hover/focus/disabled/loading/error/empty，必要时添加 success/undo。
5. **动效有目的**：普通控件采用 120–240ms CSS，优先 opacity/transform；必须尊重 `prefers-reduced-motion`。
6. **无障碍**：使用原生语义元素、可见焦点、键盘可操作。复杂弹窗/选择控件优先成熟的无障碍原语。
7. **布局**：默认内容区、边栏与卡片尺度统一；手机端不应发生页面级横向滚动。
8. **做减法**：避免无任务意义的颗粒噪声、渐变大球、玻璃堆叠、伪图表、装饰性标签。
9. **尊重项目架构**：已有 SCSS 不强行改 Tailwind；已有组件不一次性重写。先改 Token，再逐一替换组件。
10. **验证**：每次修改需要检查移动端、暗色主题、键盘、对比度与浏览器报错；不能把未执行的测试说成已通过。

## 交付前自问

- 是否可以删掉 20% 的文字而不影响使用？
- 页面是否清楚表达主操作与次操作？
- 多个组件的 padding / radius / icon size 是否一致？
- 切换主题和焦点时是否仍可读？
- 这套 UI 是否针对当前产品的真实内容，而不是复刻一个通用 SaaS 模板？
