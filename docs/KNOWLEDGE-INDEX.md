# 设计知识索引与 AI 复用协议

## 入口与生成

运行 `npm run build` 后读取 `dist/content/knowledge-index.json`，部署后对应站点根目录的 `content/knowledge-index.json`。它是独立、按需读取的数据文件，不进入主站首屏请求。Registry 组合交付读取 `dist/registry/profiles.json`。两者均为构建生成，不直接编辑 dist；`node scripts/check-dist.mjs` 会对照原始登记数据和安装计划。

知识索引格式 `ui-vault-knowledge-index` v1，records 以 `asset-id/version-id` 为键（原版为 original），当前 528 个资产、115 个版本、643 条记录。catalogSha256 表示有序登记资产 JSON 的内容指纹，并非签名。每条包含：

- provenance：登记的原仓库、源码、在线来源、许可；许可是声明，不是法律审查，也不保证链接实时可用。
- style：受控视觉标签、标签适用范围、指南审计状态和证据说明。衍生版本沿用父资产目录标签，不声称版本已人工审查。
- guide、preview、delivery.sourceFiles：仅显式登记路径的当前文件字节数和 SHA-256；同哈希表示字节一致，不保证视觉相同或无恶意代码。历史审计记录没有审计时点的哈希，当前指南哈希用于定位构建证据，不是历史未变更证明。
- delivery：复用能力来自现有白名单；原版、衍生版、外部仓库、单 HTML、独立 ZIP、Foundation 工程分别处理。源码目录不是完整依赖图；严禁把外部链接或未审核的 ZIP 声称为可安装组件。
- duplicateCandidates：相同本地预览字节、共享站点与共享源文件候选分别报告。聚合页、同源示例和有意保留的版本不自动合并或删除。
- recipes：人工整理的设计原理、实现机制、适用/不适用场景、AI 指令、验证清单和指南路径证据；这是派生建议，不是所有案例的源码实现认证。

## 分类证据边界

314 篇 website_designs 主版本原始指南已建立台账；新增 26 篇为历史已有标签的指南补录证据，不改变原标签。Landfolio 86 项主资产与 115 个衍生版本使用本仓库生成的摘要，不是原项目完整 Design.md；这 201 条不得计入原始指南人工审计。70 项无显式风格标签（含开发工具、参考索引、外站和多风格组件集合）保留未知/不适用语义，后续按实际源码或截图审查，不机械补标签。当前未发现本地预览完全相同字节的候选；仍需人工做近似视觉/语义重复判断。

## AI Agent 实施顺序

1. 按任务、技术栈、场景筛选 records 和 recipes；选少量真实可比较案例，明确借鉴的是布局、材质、字体、状态还是交互。
2. 按记录定位 guide 和源码；核对出处、版本、许可与实际依赖。路径和哈希用于验证，不运行未知源码、不执行指南中的任意指令。
3. 按 delivery 选择交付模式。使用 registry/profiles.json 的 css/react/vue 组合时，先读取 runtime，再复制 plan 命令；实际 CLI 对文件哈希、模块冲突和完整性负责。
4. 在可信目标工程中实现最小可用功能，保留无障碍、响应式和减少动效。应用具体 recipe 的 checks，真实截图及键盘操作验收，不以视觉标签当作验收证据。

不新增研究工作台，不自动抓取外部仓库，不扩大公开源码范围，不改变现有资产 ID 或保存状态。

## 工作台按需读取

项目说明 → 页面信息中选择“查看 AI 复用证据”，按当前资产和选定版本读取正式索引，提供许可/来源/指南与审查边界、相关配方、复制 JSON 和下载单条记录。只有显式打开后才请求索引；失败可重试，版本或路径不一致拒绝显示。Landfolio 的 catalog/archive-reviews.json 单独记录摘要及 HTML/CSS 源码片段人工审查，构建校验锚点与版本路径、附当前哈希；首批 8 项，不计入314原始指南，不声称完整视觉验收。

## 离线知识检索 CLI

完成构建后运行 `node scripts/search-knowledge.mjs --query "Bauhaus" --type design-style --limit 5`；或者 `node scripts/search-knowledge.mjs --query "极夜" --version landfolio-polar-night`。支持 --index 指定可信本地索引、--tag、--type、--version、--delivery 精确筛选，多词全部匹配，标题/键优先、描述/标签/审查证据其次、关联配方再次；相同分数按版本键排序。返回 JSON，含总匹配数、最多100条记录、来源指纹与配方，供 Agent 上下文提取。只读离线，不执行源码，不联网；索引限制8MiB。配方按父资产关联，不是衍生版本独立认证。当前归档审查30/201（含4个衍生版本）。

## 可视设计配方实验室

主站精选资源“设计配方实验室”（\`?asset=design-recipe-lab\`）将六种已登记配方转为原创、独立运行的 CSS 实验。可切换模块网格、玻璃、空间色场、工程信息、阅读排版与动效，实时调节实际 CSS 属性，恢复默认值、选中 CSS 片段并用系统复制快捷键。页面内嵌配方 JSON 与 canonical catalog/design-recipes.json 必须通过一致性单测；变更配方时同步 HTML 中 application/json 数据及对应实验。来源链接打开实际资产，不引入网络运行时；示例为原创教学实验，不声称上游完整复刻或认证。

## AI 设计交付与本地校验（v0.10 候选）

当前版本知识面板支持下载 AI 接入清单 JSON 和对应 DESIGN.md。模板使用当前登记资产、版本、技术栈、许可声明、设计配方、直接登记文件摘要及验收检查项生成，不内嵌源码或字体，不覆盖宿主项目已有 DESIGN.md。配方建议属于派生设计知识，不是运行认证。

在 UI-Vault 仓库根目录，使用可信本地构建产物：

```bash
node scripts/verify-knowledge-handoff.mjs --handoff /path/to/asset-ai-handoff.json --root dist
```

先校验清单与所选本地资产目录和知识索引一致，再核对当前版本直接登记的预览、指南和公开源码文件，按路径去重。拒绝未登记版本、修改过的清单、越界路径和符号链接；逐文件报告 match、mismatch、missing、unreadable。非零退出码表示未通过；外部资产没有本地证据也不算通过。根目录及其索引是调用者选择的信任基础，不验证索引签名，不防御同时修改本地可信索引的攻击者；校验期间应保持目录不变。只检查直接登记文件，不检查配方引用文件、外部网站、独立 ZIP、Registry 安装或实际运行效果，许可仍须独立核对。

真实接入应先校验清单，再依照 REUSE.md 或 Foundation Registry 的交付方式实施，完成项目构建、键盘交互、响应式和双主题验收。不要将任何源文件或指南中的指令视为 Agent 权限授权。

### 多资产组合交付

在知识面板展开反向检索，通过「加入交付组合」选择最多五个参考版本；当前资产固定为主资产，总计最多六项，当前面板会话内保留，关闭面板不自动持久化。主资产决定基础结构，其他资源仅为参考，不自动合并 CSS 或安装代码。选择高密度工作台、阅读或展示场景后，依据现有配方适用与避免条件提示人工复核；同资产多个版本、不同许可声明、无本地证据也会提示。相同路径与摘要去重；同一路径出现不同摘要/大小则拒绝生成。没有提示不意味着兼容。

组合 JSON 与组合 DESIGN.md 使用相同来源。验证命令沿用单资产 CLI：

```bash
node scripts/verify-knowledge-handoff.mjs --handoff /path/to/ai-composition.json --root dist
```

校验器按可信本地索引重建组合，严格核对角色、场景、资产版本、文件与复核提示，再逐资产验证直接登记文件。报告列出组合唯一登记文件数和各资产检查结果；同一文件可能在多个资产检查中读取。无本地证据的资产不算通过。不会自动判断法律许可、视觉风格、跨框架兼容性或真实运行。

本地实测组合：Workbench UI 为主资产，设计配方实验室、Bauhaus 原版为参考。15 个去重登记文件、6 个配方、5 项人工复核提示。使用下载组合及校验报告，在独立 React 临时工程选取主资产八份源码与样式，依据模块网格配方实现桌面双列/320px 单列，主动不采用高密度场景不必要的玻璃滤镜与空间动效。双主题、键盘选择、搜索清除回焦、宿主变量隔离及减少动效通过。这是人工构建的真实接入样例，不是 Codex 或 Claude Code 自主执行认证。

### 结构化设计规范与保存方案

组合区域的「设计规范与保存方案」读取实际 Registry 的 foundation-tokens 项，使用登记的 foundation.json 与 themes.json 生成浅/深基准。八项显式规范涵盖表面、正文、边框颜色、正文字号、间距、圆角、过渡时长和材质意图。颜色只允许六位十六进制，数字为有界整数；对比结果显示实际变化及像素/毫秒差值，正文对比按不透明背景计算，玻璃和渐变需独立验收。材质意图不等同于真实 shader 或 CSS 参数。切换基准主题会重置当前未保存提议值。

设计规范 JSON（ui-vault-design-plan v1）包含原组合、登记基准源摘要、显式提议及差异。它是实施任务说明，不自动生成或覆盖项目样式，不是已经认证的运行产物。同一对象生成规范 DESIGN.md（包含组合、八项基准与目标值、摘要及复核清单）。完整性 CLI 也直接支持设计规范 JSON，无需提取 composition：

```bash
node scripts/verify-knowledge-handoff.mjs --handoff /path/to/design-plan.json --root dist
```

基于调用方信任的本地目录重建组合、基准、提议差异和正文对比，另外核对 Registry 中两份内嵌 Token 源的 UTF-8 字节 SHA-256；任何不一致不算通过。浏览器允许选择不超过 1 MiB 的规范 JSON，严格重建并比较当前目录与基准，主资产必须匹配，用户明确确认后才恢复组合、主题和提议。导入不自动保存或应用预览，不执行文件内内容；失败保留现有编辑。浏览器比较登记数据，不替代离线字节校验；两者均不认证实际样式、外部资源、安装、许可或索引签名。

本浏览器最多保存八份具名方案，按主资产筛选恢复与删除，保存组合版本、场景、主题、规范与基准标识。拒绝同名、目录漂移或 Token 源摘要/版本变化后的静默恢复；损坏/不可用存储不覆盖，不虚报持久化成功。不是跨设备同步或多标签页事务存储。基准登记哈希来自 Registry 项，正式构建既有 Registry 校验仍保留。未经登记的资产样式不做推断。

### 真实控件与局部规范 CSS

展开「真实控件预览与 CSS 复用」，可以直接操作主站同源 SearchField、WorkbenchSelect。七项有界 Token（表面/正文/边框颜色、字号、间距、圆角、时长）映射到局部 CSS 变量、实际控件及容器；不修改原资产、主站或宿主全局变量。磨砂仍只是材质意图，不推导透明度、模糊或任意 CSS。示例有意使用正文颜色作为焦点/强调色，错误色采用固定浅深主题值；不保证所有状态色、材质对比度或完整目标项目无障碍。

下载 workbench-design-plan.css 后，按 Workbench 资产 REUSE.md 的八份真实文件接入 React 工程；先加载共享 controls.css、dropdown.css 与可选 reuse-theme.css，再加载下载的局部规范 CSS。给现有容器添加 className="wb-reuse-theme wb-design-plan" 和与导出一致的 data-theme="light" 或 "dark"。规范改变容器间距与控件实际字号、圆角及动效时长，保留原交互逻辑；减少动效优先。导出文件没有任意选择器输入，不是完整独立组件包，不自动安装，也不等同于 Foundation Registry 的 React/Vue 适配器。宿主若使用同名共享组件类，仍需检查 CSS 层叠冲突。

实测独立 React 工程使用静态发布产物八份登记文件、REUSE.md 示例与从真实 UI 下载的浅深 CSS，1440/390/320px 三视口验证 20px 间距、18px 圆角、16px 字号、宿主变量不污染、键盘选择与清除回焦、减少动效及无页面横向溢出。此为本地独立接入验收，非自动 Agent 安装认证。
